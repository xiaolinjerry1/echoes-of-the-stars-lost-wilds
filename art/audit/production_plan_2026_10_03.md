## 4. 推荐材质生产路线

采用 **Blender 材质库 + UV + 烘焙 + 重点部位纹理绘制**，全部美术产出仍在 Blender 完成。先做铁剑材质样板与野狼完整角色样板，通过后才批量处理。

1. **检查可用性并修拓扑。** 先打开对应 `.blend` 检查关节附近是否有可变形拓扑，是否为互相穿插的独立几何体。巨兽目前导出仅 800 三角面，嫩芽 216；面数本身不判定质量，但不能假定增加 2K 贴图就能补足轮廓和关节。按观察结果修肩胯、膝肘、口鼻、手指等关键结构。角色不超过 20k tris，怪物不超过 10k，单个场景道具不超过 5k。
2. **展开 UV。** 9 个无 UV 模型先展开，其余检查拉伸/重叠；脸、手、动物头部、武器握柄优先保证像素密度。角色使用手工接缝，硬表面可辅助自动展开。独特 AO 烘焙区避免重叠，留足 mipmap 边距。
3. **建立共享材质。** 做钢铁、皮革、布料、木、石、苔藓、毛皮/兽皮、植物八类，按资产调整方向、尺度和磨损。毛皮要有毛流，布料要有编织尺度；基础色尽量不带定向光影，避免游戏昼夜光照与贴图阴影冲突。
4. **烘焙与导出。** 单独保留 Albedo、Normal、Roughness、Metallic、AO PNG；有符文/熔岩的资产追加 Emission/遮罩。角色按 2K；道具、地形、植被按 1K。法线采用切线空间，法线与数值贴图按非颜色数据处理；Albedo/彩色发光按颜色纹理处理。Blender Cycles 支持把程序材质、基础色与法线烘焙到有 UV 的网格上。[官方烘焙说明](https://docs.blender.org/UATEST/manual/en/4.5/render/cycles/baking.html)
5. **GLB 打包。** 导出前将程序节点结果接为图片贴图；Roughness 放 G、Metallic 放 B，可以与 R 通道 AO 合成 ORM，独立 PNG 仍保留归档。仅将金属度写成 0 或 1 是合理材质表达，但为遵循本项目全套归档要求仍可生成对应纯值贴图，不应给皮肤人为添加金属噪声。[Blender glTF 材质规范](https://docs.blender.org/manual/en/3.3/addons/import_export/scene_gltf2.html)

AI 图片可作为配色和表面细节参考，但不能把单张带灯光的角色图直接当成可用 UV 贴图，更不能从一张图可靠获得整套物理一致的 Normal/Roughness/AO。这个项目优先建立能重复烘焙的 Blender 源材质，接缝与细节留在 Blender 内修正；不需要先购买贴图服务。

## 5. 推荐骨骼生产路线

| 类型 | 建议方法 | 最小动画交付 |
|---|---|---|
| 法师/祭司/NPC | Blender Rigify 人形模板或简化人形控制架；按模型对齐、自动权重初稿、人工修权重；衣摆加辅助骨 | idle、walk、run（需要者）、cast、hit、death；NPC talk、巡林者 wounded |
| 第一人称手臂 | 单独双臂与手指控制架，手腕与握剑姿态精修 | idle、3 段 attack、block、hit、charge/sweep/roar、回响施法 |
| 狼/猪/巨兽 | Rigify Wolf/Basic Quadruped 作为起点，依实际脊柱/肩胯/足爪调整；巨兽另加下颌、冠冕等需要控制的部位 | locomotion、attack、hit、death；猪 charge/stun，巨兽 sweep/charge/summon/stagger/recover |
| 嫩芽 | 自定义少量骨骼控制球茎、根足、叶片 | idle、walk、heal、death |

Rigify 的人形/四足模板用于加快控制架搭建，仍需按模型对齐骨位并完成蒙皮，不是“一键给任意模型转骨骼”。模板选择依据官方说明，具体本机插件是否启用尚未验证。[Rigify 官方使用说明](https://docs.blender.org/manual/en/latest/addons/rigging/rigify/basics.html?highlight=pose+mode)

制作顺序：检查原始骨架 → 修拓扑并冻结尺寸 → 对齐 Rest Pose → 建控制架/变形骨 → 蒙皮与权重归一化 → 极限动作测试 → 制作动画 → 将约束/IK 求解结果烘焙到导出骨架 → GLB 重新导入验证。若源文件已有合格骨架，修正导出即可，不重复绑定。建议最多 4 个有效骨骼影响/顶点作为项目初始预算，再通过画面验证。

优先采用原地循环动画，由现有 CharacterBody/AI 控制位移；攻击判定、冷却和伤害仍由现有战斗系统负责，动画对齐前摇与命中时刻，避免动画与脚本同时移动根节点。NPC 与法师可统一骨架并共享适用动作，四足需要单独规则；不能只改骨名就认定重定向成功。Godot 4.6 对人形提供 BoneMap / SkeletonProfileHumanoid，并要求处理 Rest Pose 差异。[Godot 4.6 骨骼重定向](https://docs.godotengine.org/en/4.6/tutorials/assets_pipeline/retargeting_3d_skeletons.html)

## 6. 本项目必须配套处理的接线点

- `base_enemy.gd:_load_model()` 当前只实例化模型。需要找到导入的 AnimationPlayer，并接入动画状态控制，使 PATROL/CHASE/ATTACK/STAGGERED/DEAD 对应正确动画；导出成功不代表角色会自动走动挥击。
- `fp_arms.gd:_collect_arm_materials()` 假设左右臂是 CapsuleMesh。真实手臂替换后必须更新材质查找、符文与手套接口；WeaponMount 接到手部骨骼挂点，并校正握柄原点。
- `npc.gd` 同样依赖胶囊身体材质，需增加模型挂点和外观/动画接口。
- `terrain_builder.gd:_find_mesh_instance()` 只取第一个 ArrayMesh。树/岩石交付需保持兼容的单 Mesh 多 Surface 结构；若拆成多个网格，必须同步支持多个 MultiMesh，否则存在丢失部分模型的风险。
- 资产规范规定游戏中正面 +Z，但历史 ASSET_LOG 记录敌人导入后为 -Z。统一导出标准时要同时校对 AI 朝向与视觉挂点旋转，避免角色倒着走。武器、宝箱 Lid、风车轮毂和悬浮精灵的原点是用途例外，保留并登记，不能统一强行归零到底部。
- 保留现有碰撞、伤害代理、导航、保存 ID 和模型路径约定；视觉改造不应使攻击距离、宝箱状态和任务引用失效。

1. **样板批**：铁剑完成 UV/PBR/归档；野狼完成拓扑检查、PBR、绑定、基础动作与 Godot 接线。前者验证材质链路，后者验证完整角色链路。
2. **近景与战斗批**：真实第一人称手臂、野猪、法师/祭司、巨兽、嫩芽。复用样板的材质与导出工具。
